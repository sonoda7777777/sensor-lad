---
description: .inoファイル（Arduinoスケッチ）のコードレビューを行う
---

このスキルを実行した際、以下の手順に沿って`.ino`ファイルのレビューを行う。

## 前提

- `CLAUDE.md`に記載された「.inoファイルの生成・編集時のルール」をレビュー基準とすること
- **このスキルではコードを書き換えない**。指摘のみ行い、修正は別途ユーザーの指示を待つ

## 手順

1. **対象ファイルの特定**
   - ユーザーから対象ファイルが指定されていればそれを使う
   - 指定がない場合は、ユーザーに対象を確認する（`src/`配下に複数の`.ino`がある場合は一覧を提示）

2. **コードの読み込み**
   - 対象`.ino`ファイルを読み込み、全体構造を把握する

3. **レビュー観点でのチェック**
   以下の観点で問題点を洗い出す。

   ### 必須チェック項目（CLAUDE.md準拠）
   - **C++記法**: Arduino方言に過度に依存していないか、C++として不自然な書き方がないか
   - **`const` / `constexpr`の漏れ**: 不変の変数に`const`が付いていない箇所
   - **不適切な型**: 値の範囲に対して型が大きすぎる／符号の有無が不適切／安易な`int`の使用

   ### コード品質
   - **マジックナンバー**: 名前のない数値リテラルが直接書かれていないか
   - **命名**: 変数名・関数名・定数名が役割を表しているか、命名規則が一貫しているか
   - **スコープ**: 不必要にグローバル化されている変数がないか

   ### 構造
   - **関数の責務**: `loop()`や個別関数が複数の責務を持っていないか
   - **ネストの深さ**: `if`/`for`が深くネストして読みづらくなっていないか
   - **重複コード**: 同じ処理が複数箇所に書かれていないか

   ### 安全性・正確性
   - **桁あふれリスク**: `uint8_t`の加算・乗算でオーバーフローしうる箇所
   - **未初期化変数**: 初期値なしで使われる変数
   - **`delay()`の多用**: ブロッキングが問題になりうる箇所
   - **`String`クラスの使用**: メモリ断片化リスク（AVR系の場合）
   - **割り込み関連**: ISR内での重い処理、`volatile`漏れ

   ### 可読性
   - **冗長／不正確なコメント**: コードを読めばわかる説明、または実装と乖離したコメント
   - **コメント不足**: なぜその処理が必要かが非自明な箇所での説明不足

4. **レビュー結果の提示**
   以下のフォーマットで結果をまとめて提示する。

   ```
   ## レビュー対象
   <ファイルパス>

   ## 重大度別の指摘
   ### 🔴 要修正（バグ・安全性に関わる）
   - L<行番号>: <指摘内容> / <修正案>

   ### 🟡 推奨修正（CLAUDE.md違反・品質低下）
   - L<行番号>: <指摘内容> / <修正案>

   ### 🔵 任意（スタイル・好み）
   - L<行番号>: <指摘内容> / <修正案>

   ## 総評
   <全体の所感を2〜3行で>
   ```

   - 指摘は **行番号付き** で行うこと
   - 各指摘には **具体的な修正案** を添えること
   - 問題がない観点については触れず、指摘事項だけを書く
   - 重大度別に分類し、優先度がわかるようにする

5. **次のアクションの確認**
   - レビュー結果を提示した後、ユーザーに「修正を実施するか」「特定の指摘のみ対応するか」を確認する
   - 修正実施の指示があれば`/ino_refactor`スキルの利用を提案する

## やらないこと

- **コードの書き換え**（このスキルはレビュー専用）
- 機能仕様への踏み込んだ提案（明らかな不具合を除く）
- 動作確認・実機検証（ユーザーの作業範囲）
