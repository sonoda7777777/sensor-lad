description: .inoファイル（Arduinoスケッチ）をリファクタリングする
---

このスキルを実行した際、以下の手順に沿って`.ino`ファイルのリファクタリングを行う。

## 前提

`CLAUDE.md`に記載された「.inoファイルの生成・編集時のルール」を必ず遵守すること。

## 手順

1. **対象ファイルの特定**
   - ユーザーから対象ファイルが指定されていればそれを使う
   - 指定がない場合は、ユーザーに対象を確認する（`src/`配下に複数の`.ino`がある場合は一覧を提示）

2. **現状の把握**
   - 対象`.ino`ファイルを読み込み、以下を整理する
     - 使用しているピン・センサ・ライブラリ
     - `setup()` / `loop()` の構造
     - 変数の型・スコープ・可変性

3. **リファクタリング観点の適用**
   以下の観点でコードを見直し、必要な修正を行う。

   ### コード品質
   - **C++記法の遵守**: Arduino方言に依存せず、C++として正しい構文で書く
   - **`const` / `constexpr`の付与**: 不変の値（ピン番号・しきい値・遅延時間など）はすべて`const`化する
   - **適切な型選択**: 値の範囲に応じて`uint8_t` / `uint16_t` / `uint32_t` / `float`等を使い分ける（安易な`int`を避ける）
   - **マジックナンバーの排除**: コード中の数値リテラルは名前付き定数に置き換える
   - **命名**: 定数は`UPPER_SNAKE_CASE`、変数・関数は`lowerCamelCase`を基本とする

   ### 構造
   - **関数分割**: `loop()`内の処理が長い・責務が複数ある場合、適切な単位で関数に切り出す
   - **グローバル変数の最小化**: 必要最小限に留め、可能ならローカル化する
   - **早期returnの活用**: ネストの深い`if`は早期returnで平坦化する

   ### 可読性・保守性
   - **不要なコメントの削除**: コードを読めばわかる説明コメントは削除する
   - **必要なコメントの追加**: 「なぜそうしているか」が非自明な箇所にのみコメントを残す
   - **重複コードの統合**: 同じ処理が複数箇所にあれば関数化する

4. **変更内容の提示**
   - 修正前後の差分（または変更点の要約）をユーザーに提示する
   - 動作が変わる可能性のある変更（型変更による桁あふれ、タイミング変化等）は明示的に警告する

5. **コンパイル確認の促し**
   - リファクタリング後はArduino IDEまたは`arduino-cli`でコンパイルが通ることをユーザーに確認してもらう
   - ハードウェア動作の検証は実機でユーザーに実施してもらう

## やらないこと

- 機能追加・仕様変更（リファクタリングの範疇を超える変更は行わない）
- ライブラリの差し替え（ユーザーから指示がない限り）
- ファイル名・ディレクトリ構成の変更（指示がない限り）
